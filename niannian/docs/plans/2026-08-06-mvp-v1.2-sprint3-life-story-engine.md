# 《念念年年 MVP V1.2》Sprint 3 开发文档

> **Sprint 名称：** Life Story Engine（人生故事引擎）  
> **版本：** 1.0  
> **阶段：** 产品工程化 · 关键节点  
> **执行：** cker + Cursor

---

## 一、为什么改名

Sprint 3 不再叫「故事生成」。

从这一阶段起，AI 的价值不是「调用大模型写一段作文」，而是：

**根据 Memory Card 自动发现主题，并组织成多个可阅读、可编辑、可版本化的 Story。**

产品技术主线（贯穿 V1.2 → V1.3）：

```
Photo → Memory Card → Scene → Story → Chapter → Life Movie
                              ↑ Sprint 3          ↑ Sprint 4
```

---

## 二、Sprint 目标

完成 **Story Engine V2**，跑通完整链路：

```
Memory Card → Scene（聚类）→ Theme（主题）→ Story（成稿）→ 故事库
```

**验收心智：** 用户上传 ~20 张照片后，系统产出 **3–5 个不同主题的故事**，而不是 20 张 → 一篇作文。

## 四、数据模型

### 4.1 升级 `stories`（迁移 V1 → V2）

```sql
-- 新增 / 变更字段（迁移脚本保留旧 description → summary）
ALTER TABLE stories ADD COLUMN summary TEXT DEFAULT '';
ALTER TABLE stories ADD COLUMN theme TEXT DEFAULT '';
ALTER TABLE stories ADD COLUMN cover_photo_id TEXT;
ALTER TABLE stories ADD COLUMN updated_at TEXT;
-- 保留 connection_action / timeline 作兼容，V2 逐步迁到 compose 输出结构
```

V2 语义：

| 字段 | 说明 |
|------|------|
| `title` | 故事标题 |
| `summary` | 一句摘要（原 `description`） |
| `theme` | 主题：成长 / 陪伴 / 团圆 / 传承 / 第一次 / 离别 / 探索 / 爱 … |
| `cover_photo_id` | 封面照片 ID |
| `photos` | **deprecated**，改由 `story_memory_cards` 驱动；迁移期双写 |

### 4.2 新增 `story_memory_cards`

```sql
CREATE TABLE story_memory_cards (
  story_id TEXT NOT NULL,
  memory_card_id TEXT NOT NULL,  -- 实际存 photo_id，对应 memory_cards.photo_id
  order_index INTEGER NOT NULL DEFAULT 0,
  scene_id TEXT,                 -- 可选：所属 Scene 分组标识
  PRIMARY KEY (story_id, memory_card_id),
  FOREIGN KEY (story_id) REFERENCES stories(id)
);
```

**关键：** 一张 Memory Card 可出现在多个 Story（如「爸爸骑车」→ 成长故事 + 父爱故事）。

### 4.3 新增 `story_versions`

```sql
CREATE TABLE story_versions (
  id TEXT PRIMARY KEY,
  story_id TEXT NOT NULL,
  version INTEGER NOT NULL,
  theme TEXT NOT NULL DEFAULT '',
  title TEXT NOT NULL DEFAULT '',
  summary TEXT NOT NULL DEFAULT '',
  content TEXT NOT NULL DEFAULT '[]',  -- JSON: 章节段落 [{photoId, memorySnippet, narrative}]
  regen_mode TEXT,                       -- keep_theme | rediscover_theme | reorder | full
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  FOREIGN KEY (story_id) REFERENCES stories(id)
);
CREATE INDEX idx_story_versions_story ON story_versions(story_id, version DESC);
```

### 4.4 Memory Card · Story Layer + 叙事层

**叙事层 `narrative_frame`**（Sprint 3 前导，已实现）— 每张照片在 Story 中的「镜头语言」：

| 字段 | 说明 |
|------|------|
| `storyline` | 故事线角色：铺垫 / 日常 / 陪伴 / 探索 / 转折 / 高潮 / 告别 / 余韵 / 纪念 |
| `storylineNote` | 组合成故事时的叙事功能（一句话） |
| `shotType` | 景别：特写 / 中景 / 全景 / 合影 / 自拍 / 抓拍 / 空镜 |
| `shotNote` | 镜头语言描述（构图、视角、画面张力） |
| `shotTags` | 镜头标签，写入第五层「叙事标签」 |

**Story Layer `story_layer`**（Sprint 3.1）— 聚类用的语义字段：

```typescript
interface StoryLayer {
  scene_type: string;    // 尝试 | 成长 | 陪伴 | 告别 | 庆祝 | 探索
  change: string;        // 不会→学会 | 陌生→熟悉 | 害怕→勇敢 | 依赖→独立
  relationship: string;  // 父亲 | 母亲 | 祖孙 | 夫妻 | 兄弟 | 朋友 | 自己
  meaning: string;       // 成长 | 勇气 | 责任 | 陪伴 | 传承 | 梦想 | 家庭 | 爱
  importance: number;    // 1–5，AI 评分，决定 Story 优先级与封面候选
}
```

**写入时机：** 照片 AI 解析 / 结合用户补充重新理解 时，与 understanding 一并生成。

## 五、Story Engine 架构

```
lib/story-engine/
├── index.ts          # runStoryEngine(familyId, options)
├── cluster.ts        # Memory Cards → Scenes
├── theme.ts          # Scene → Theme + Top3 标题建议
├── compose.ts        # Theme + Cards → Story 正文（章节式）
├── cover.ts          # 选 cover_photo_id
└── types.ts          # Scene, Theme, StoryDraft, RegenMode
```

### 5.1 `cluster.ts` — 聚类为 Scene

**输入：** 家庭下全部（或选定）Memory Cards + Story Layer  
**输出：** `Scene[]`，每个 Scene 含 `memoryCardIds[]`

**聚类信号（Embedding 仅辅助，非唯一依据）：**

1. 人物重叠（`people` / `relationship`）
2. 关系类型（`relationship`）
3. 变化弧线（`change`）
4. 意义标签（`meaning`）
5. 主题相近（`scene_type`）
6. 时间连续性（`taken_at`）
7. **故事线角色（`narrative_frame.storyline`）** — 铺垫→发展→高潮 可编排
8. **景别节奏（`narrative_frame.shotType`）** — 特写/全景交替

**目标 Scene 数：** 3–5（照片少时允许 1–2）。

### 5.2 `theme.ts` — 提炼主题

**输入：** 一个 Scene 内的 Memory Cards  
**输出：**

```typescript
{
  theme: '成长',
  titleCandidates: ['第一次放手', '成长的夏天', '爸爸一直都在'],
}
```

### 5.3 `compose.ts` — AI 成稿

**输入：** Theme + Memory Cards（含用户补充 `user_notes`）  
**Prompt 原则：**

- 不要编造事实
- 围绕主题组织
- 重点描述**变化过程**，少描述结果
- 语言自然，像纪录片，不像作文

**输出：** 章节式结构（非长文章）：

```typescript
type StorySegment = {
  photoId: string;
  memoryFacts: string;   // 来自 Memory Card 事实层摘要
  narrative: string;     // AI 叙述段落
};
```

### 5.4 `cover.ts` — 封面选择

优先级：

1. `importance` 最高
2. 人物清晰
3. 画面质量（暂用 heuristic / 后续 vision 评分）

## 六、用户流程

```
上传照片 → AI 解析 → Memory Card（含 Story Layer）
       ↓
  点击「生成故事」（家庭页 / 照片库）
       ↓
  Story Engine（cluster → theme → compose × N → cover）
       ↓
  写入多个 Story + story_memory_cards + story_versions v1
       ↓
  故事库 /stories → 详情 /stories/[id]
```

## 七、页面与 API

### 7.1 页面

| 路由 | 说明 |
|------|------|
| `/stories` | 故事库列表：封面、标题、摘要、主题、照片数 |
| `/stories/[id]` | 详情：标题 / 主题 / 摘要 → **时间轴章节**（照片 → Memory → AI 叙述）循环 |
| `/family/[id]/story` | 保留或重定向到 `/stories?familyId=` |

**详情页底部四按钮：** 分享 · 下载 · 编辑 · 重新生成

### 7.2 API（新增 / 改造）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/story/generate` | `{ familyId }` 跑完整 Story Engine，返回 3–5 个 Story |
| GET | `/api/story?id=` | 单个 Story + segments + memory cards |
| PATCH | `/api/story` | 编辑标题 / 摘要 / 排序 / 删图 |
| POST | `/api/story/regenerate` | **改造**：四种模式 + 写 version |
| GET | `/api/story/versions?storyId=` | 版本列表 |
| POST | `/api/story/versions/restore` | 恢复指定版本 |

### 7.3 四种重新生成模式

| 模式 | `regen_mode` | 行为 |
|------|--------------|------|
| 保持主题，重新组织语言 | `keep_theme` | 同 memory cards + theme，重写 compose |
| 保持照片，重新发现主题 | `rediscover_theme` | 重跑 theme + compose |
| 保持主题，重新排序照片 | `reorder` | 重排 story_memory_cards + 局部 compose |
| 全部重新生成 | `full` | 重跑 cluster → theme → compose |

**原则：** 新版本 **追加** 到 `story_versions`，默认不覆盖；用户可选恢复。

## 十、Sprint 4 预览 · Life Movie Engine

Sprint 4 不再定义为「老人模式」，而是 **Life Movie Engine（人生电影引擎）**：

当 Story Engine 稳定产出多个 Story 后，下一步将多个 Story 编排为 **Chapter（章节）** 和 **Movie（人生电影）**。

```
Photo → Memory Card → Scene → Story → Chapter → Life Movie
```

Sprint 4 核心：Story 聚合 → 章节编排 → 可播放/可分享的「人生电影」体验（欣赏模式作为 Movie 的一种消费形态，而非 Sprint 4 的全部）。

## 十一、风险与 MVP 裁剪建议

| 风险 | 应对 |
|------|------|
| 20 张 × 多 Story AI 调用慢 | 3.3 做异步 + 进度；compose 可并行 |
| Embedding 依赖未接入 | 3.2 先用 **规则聚类 MVP**，embedding 作 enhancement |
| V1 stories 数据兼容 | 3.1 双写 + 迁移脚本，不破坏现有家庭数据 |
| 范围过大 | **3.1→3.3 为 P0**（能生成多故事）；3.4–3.6 可迭代 |

**建议第一刀：** 3.1 Story Layer + 3.2 cluster/theme/compose + 3.3 generate API，先让「20 张 → 3 个 Story」在 CLI/API 层跑通，再做 UI。
