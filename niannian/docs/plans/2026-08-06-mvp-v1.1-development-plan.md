# 念念年年 MVP V1.1 二次开发计划

> **版本：** V1.1（AI 记忆发现版）  
> **阶段：** 产品工程化（How）  
> **执行：** cker + CodeBuddy

## 目标

将 Demo 升级为真正可验证的 AI 家庭记忆产品。

**核心 pivot：**

- ❌ AI 聊天
- ✅ AI 理解照片 → 引导补充 → 生成故事

**关键架构决策：** Memory Card（记忆卡）作为中间层，产品底层从「照片驱动」升级为「记忆驱动」。

```
照片 → AI解析 → 用户补充 → Memory Card → 聚类 → 故事
```

## Memory Card 数据结构

```
MemoryCard {
  // 事实层
  photo_id, taken_at, location, people[], action

  // 理解层（AI 推测）
  emotions[], changes[], significance

  // 用户层（Sprint 2）
  user_notes, voice_transcript, ai_questions[]

  // AI 层
  tags: { objective, behavior, change, family_value }
  story_ids: string[]
}
```

---

## 标签系统 V2（四层）

1. **客观标签** — 人物、时间、地点
2. **行为标签** — 拥抱、骑车、旅行、做饭
3. **变化标签** — 第一次、重新开始、毕业、长大、重逢
4. **家庭价值标签** — 爱与滋养、冒险成长、创造玩乐、传承根基、自定义

---

## AI 工作流

```
上传照片 → 图片解析 → 生成 Memory Card → 用户补充 → 重新理解
→ 故事聚类 → 生成故事 → 保存 Story
```

---

## Sprint 里程碑

### Sprint 1（1 周）— 照片理解 ✅ 进行中

**目标：** 完成照片理解，每张照片生成一张记忆卡。

- [x] 创建本计划文档
- [x] 修复基础 bug（family 详情页、stories API、share 页）
- [x] 扩展 DB schema（memory_cards + tags 四层）
- [x] 升级 AI 解析 prompt（结构化 + 情绪推测）
- [x] Memory Card API + Photo Library API
- [x] Memory Card 页面 + 照片网格
- [x] 接入 PhotoUploader（拖拽/HEIC）

**交付：** 每张照片都能生成并查看一张 Memory Card。

### Sprint 2（1 周）— 用户补充

- 文本输入 + 语音输入（STT）
- AI 固定提问（2–3 个/张）
- 结合用户补充重新理解 → 更新 Memory Card
- [x] 记忆卡筛选（标签/状态/关键词）
- [x] 语音检索筛选（Web Speech API）
- [x] Google Photos 导出 JSON 元数据还原（拍摄时间/GPS/描述/人物）

### Sprint 3（1 周）— 故事生成

- Story Engine V2：Embedding 聚类 → 3–5 个故事
- 故事展示页升级

### Sprint 4（1 周）— 记忆库闭环

- Story Library + Photo Library 完整 UX
- 标签筛选、分享、下载
- 欣赏模式（老人端）
- Supabase 迁移（schema 稳定后）

---

## 技术策略

- **Sprint 1–3：** 继续 SQLite + 本地文件存储（MVP 链路已跑通）
- **Sprint 4：** Supabase 迁移，Repository 接口不变
- **AI：** 火山引擎 Ark API（vision + text），含 mock fallback
