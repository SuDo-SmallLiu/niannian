# 念念年年 MVP V1.1 二次开发计划

> **版本：** V1.1（AI 记忆发现版）  
> **阶段：** 产品工程化（How）  
> **执行：** cker + CodeBuddy

## 目标

将 Demo 升级为真正可验证的 AI 家庭记忆产品。

**核心 pivot：**

- ❌ AI 聊天
- ✅ AI 理解照片 → 引导补充 → 生成故事

**关键架构决策：** Memory Card（记忆卡）作为中间层，产品底层从「照片驱动」升级为「记忆驱动」。

```
照片 → AI解析 → 用户补充 → Memory Card → 聚类 → 故事
```

## Memory Card 数据结构

```
MemoryCard {
  // 事实层
  photo_id, taken_at, location, people[], action

  // 理解层（AI 推测 — 情动理论）
  emotions[], changes[], significance
  understanding: { archetype, indicators[], valence, arousal, quadrant, emotions[] }
  change_detail: { transitions[], summary }

  // 用户层（Sprint 2）
  user_notes, voice_transcript, ai_questions[]

  // AI 层
  tags: { objective, behavior, change, family_value }
  story_ids: string[]
}
```

## 标签系统 V2（四层）

1. **客观标签** — 人物、时间、地点
2. **行为标签** — 拥抱、骑车、旅行、做饭
3. **变化标签** — 变化类型 + 人生阶段 + 情动位移（首次/告别/重聚/成长/传承/新开始/角色转换/日常沉淀）
4. **主题价值标签** — 爱与滋养、冒险成长、创造玩乐、传承根基、自定义

---

## 理解层 · 情动理论（DH2012 适配）

参考 Liu & Peng (DH2012) + Russell 环形模型，分析分两步：

1. **情动指示词** — 从画面识别视觉/场景证据（如：牵手、日落、空椅子、生日蛋糕）
2. **情动构型** — 映射到 10 个家庭情动构型，而非直接输出情绪词

| 情动构型 | 含义 |
|----------|------|
| 温暖相依 | 亲密陪伴、安静相守 |
| 欢聚庆典 | 节庆、生日等集体欢庆 |
| 探索新奇 | 第一次、新地方的兴奋 |
| 宁静安放 | 日落、阅读等低唤醒安心 |
| 成长见证 | 毕业、学会新技能等里程碑 |
| 暂别思念 | 离别、空位的牵挂 |
| 挑战突破 | 紧张尝试后的突破 |
| 仪式传承 | 年节、教手艺等代际连接 |
| 岁月回响 | 旧照对比、时光流逝感怀 |
| 日常烟火 | 做饭、吃饭等日常照料 |

**Russell 维度：** valence（效价）× arousal（唤醒）→ 四象限

## 变化层 · 人生节点

| 变化类型 | 示例 |
|----------|------|
| 首次 | 第一次走路、第一次去海边 |
| 告别 | 离家上学、送别 |
| 重聚 | 春节团聚 |
| 成长 | 明显长高、学会独立 |
| 传承 | 教包饺子、讲家族故事 |
| 新开始 | 搬新家、康复出院 |
| 角色转换 | 成为父母、毕业 |
| 日常沉淀 | 每周家庭晚餐 |

每个变化可附带：人生阶段 + 情动位移（如「紧张 → 骄傲」）

## AI 工作流

```
上传照片 → 图片解析 → 生成 Memory Card → 用户补充 → 重新理解
→ 故事聚类 → 生成故事 → 保存 Story
```

## Sprint 里程碑

### Sprint 1（1 周）— 照片理解 ✅ 进行中

**目标：** 完成照片理解，每张照片生成一张记忆卡。

- [x] 创建本计划文档
- [x] 修复基础 bug（family 详情页、stories API、share 页）
- [x] 扩展 DB schema（memory_cards + tags 四层）
- [x] 升级 AI 解析 prompt（结构化 + 情绪推测）
- [x] Memory Card API + Photo Library API
- [x] Memory Card 页面 + 照片网格
- [x] 接入 PhotoUploader（拖拽/HEIC）

**交付：** 每张照片都能生成并查看一张 Memory Card。

### Sprint 2（1 周）— 用户补充 ✅

- [x] 文本输入 + 语音输入（STT）
- [x] AI 固定提问（2–3 个/张）
- [x] 结合用户补充重新理解 → 更新 Memory Card
- [x] 记忆卡筛选（标签/状态/关键词）
- [x] 语音检索筛选（Web Speech API）
- [x] Google Photos 导出 JSON 元数据还原（拍摄时间/GPS/描述/人物）

**交付：** 记忆卡详情页可补充文字/语音、回答 AI 提问，并触发「结合补充重新理解」。

### Sprint 3（1 周）— 故事生成

- Story Engine V2：Embedding 聚类 → 3–5 个故事
- 故事展示页升级

### Sprint 4（1 周）— 记忆库闭环

- Story Library + Photo Library 完整 UX
- 标签筛选、分享、下载
- 欣赏模式（老人端）
- Supabase 迁移（schema 稳定后）

## 技术策略

- **Sprint 1–3：** 继续 SQLite + 本地文件存储（MVP 链路已跑通）
- **Sprint 4：** Supabase 迁移，Repository 接口不变
